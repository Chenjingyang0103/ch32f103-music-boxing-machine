# 7. 状态机与中断规范

> 非阻塞任务、事件上报，以及中断服务函数（ISR）的编写约定。

## 7.1 非阻塞状态机

- 采集类驱动实现为非阻塞状态机，主循环每圈调用一次，完成一步返回 1：

```c
/**
 * @brief  HCT6521 非阻塞状态机任务，主循环每圈调用一次
 * @retval 1=本次读取完成，0=尚未完成
 */
uint8_t HCT6521_Task(AdcDevNumTypedef DevNum, int32_t *OutValue)
{
    switch (pFsm->AdcFsmState)
    {
        case AdcFsmState_Idle:      { ... }
        case AdcFsmState_Reading:   { ... }
        case AdcFsmState_WaitHigh:  { ... }
    }
    return 0;   // 未完成
}
```

- 状态机状态用枚举 `XxxState_名字`，`default` 分支强制回安全态。
- 业务状态机（如 `Game_Task`）在同一 `switch` 内按状态分派，`case` 块内标明状态流转去向。

## 7.2 事件上报

- 事件上报采用“边沿触发 + 读取即清零”，避免重复触发：

```c
uint8_t Punch_IsHit(AdcDevNumTypedef DevNum)
{
    PunchRunningParamTypedef *pRun = &PunchDeviceParam[DevNum].RunningParam;
    if (pRun->HitReported)
    {
        pRun->HitReported = 0;   // 清除上报标志，防止重复触发
        return 1;
    }
    return 0;
}
```

## 7.3 中断服务函数

- ISR 短小：只置标志 / 计数，重活交给主循环。
- 共享变量 `volatile`；退出前清除中断挂起标志。
- 中断与主循环之间通过 `Get` / `Clear` 接口访问节拍量：

```c
void TIM2_IRQHandler(void)
{
    if (TIM_GetITStatus(TIM2, TIM_IT_Update) != RESET)
    {
        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
        TempTickMs++;
        GameTickMs++;
        if (GameTickMs >= GAME_TICK_PERIOD_MS)
        {
            GameTick++;
            GameTickMs = 0;
        }
    }
}
```

- CH32F103 无需 `__attribute__((interrupt("WCH-Interrupt-fast")))`；
  若保留该行需按项目现有做法注释并标注“CH32V系列才需要”。

## 7.4 阻塞式外设与主循环占用

并非所有“底层驱动”都是非阻塞的。调用前先确认单次耗时，再决定调用频率。

- `SM28_Update` 属**同步阻塞**：一帧 138 字节（`SM28_BUFFER_SIZE(136)` + 校验 + 尾随）全部按位翻转 GPIO
  发出，无 DMA、无分片，调用期间占满 CPU。
- 单帧耗时：8MHz 下使用库函数 `GPIO_SetBits` / `GPIO_ResetBits` 约 **9ms**；
  改为直接写寄存器后约 **2.5ms**。收益来自省掉跨 `.c` 文件、编译器无法内联的函数调用：

```c
    sclPort->BSHR = sclPin;           /* 等价于 GPIO_SetBits(sclPort, sclPin); */
    sclPort->BCR  = sclPin;           /* 等价于 GPIO_ResetBits(sclPort, sclPin); */
```

  寄存器写法的位时序与波形完全不变，属零风险提速；替换时旧写法以注释保留（见 [04.5 改动纪律](04-代码格式.md#45-改动纪律)）。
- **调用频率直接决定 CPU 占用**。`SM28_Update` 曾放在主循环每圈调用，致使主循环周期被拉到约 9ms，
  并连带拖慢 `HCT6521_Task`（其一次完整读取需 Idle → Reading → WaitHigh 共 3 个循环）。
  当前改为两个低频点：`main.c` 的秒变化分支（每秒一次）与 `GameLogic.c` 的 `GameState_Result`（每回合一次）。
- 进一步提升（尚未实施）：脏标记（缓冲区没变就不发） + 限速（最短发送间隔，如 50ms），
  可把总占用从约 30% 降到约 5%。注意两项都只降低**总占用**，不降低**单次阻塞时长**；
  要压低单次仍需分片状态机或改用 SPI/DMA。
- 给显示类模块加节拍时，**时基由参数传入**（如 `SM28_Task(DevNum, NowMs)`），
  不要在 Display 层 `#include "Timer.h"`，以免驱动层反向依赖业务层。
