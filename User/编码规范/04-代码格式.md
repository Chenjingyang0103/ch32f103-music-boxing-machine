# 4. 代码格式

> 缩进、括号、空格与分支写法的统一约定。

## 4.1 缩进与括号

- 缩进：**4 个空格**，不使用 Tab（重排版后的模块以 4 空格为准）。
- 括号：函数体与控制块采用 Allman 风格（左花括号独占一行）：

```c
void Punch_Reset(AdcDevNumTypedef DevNum)
{
    PunchRunningParamTypedef *pRun = &PunchDeviceParam[DevNum].RunningParam;
    pRun->state = PunchState_Idle;
}
```

## 4.2 空格

- `if` / `for` / `while` / `switch` 后加一个空格，运算符与比较符两侧加空格：

```c
for (uint8_t i = 0; i < ADC_DEV_NUM; i++)
{
    if (force > pSta->TriggerThreshold)
    {
        ...
    }
}
```

## 4.3 switch 写法

- `switch` 的每个 `case` 用花括号包裹，并按状态机语义加注释：

```c
switch (pRun->state)
{
    case PunchState_Idle:
    {
        ...
        break;
    }
    case PunchState_Track:
    {
        ...
        break;
    }
    /* 异常状态，强制回 IDLE */
    default:
    {
        pRun->state = PunchState_Idle;
        break;
    }
}
```

## 4.4 历史差异

早期文件如 `main.c`、`HCT6521.c`、`HCT6521.h`、`SM16028E.h`、`GameLogic.h`、`PunchDetect.h`
曾存在 Tab 与 2 空格缩进残留，已于全量复审中统一为 4 空格；新增与改动代码一律按本章格式对齐。

## 4.5 改动纪律

> 修改代码时只做需求要求的事，其余一律保持原样。

- **只改需求涉及的行**：不得在修改时顺手调整无关行的缩进、对齐、空行或括号位置。
- **保持既有缩进宽度**：不得把 4 空格整体重排为 3 空格或 Tab，反之亦然（本文档以 4 空格为准）。
- **不得擅自增删注释**：不新增空的 `//` 占位行，也不删除他人已有的注释。
- **不得擅自解除注释**：他人（或早先）注释掉的代码（如调试 `printf`）默认保持注释状态，
  确需放开必须先说明用途并征得同意。
- **替换实现时旧写法以注释保留**：用新写法替换旧写法时，旧的一行（或一整块）紧跟在对应新行之后，
  以 `//` 注释保留，不删除，便于对照与回退。示例见 `SM16028E.c` 中 `SM28_SendByte` 的
  `sclPort->BSHR = sclPin;` / `// GPIO_SetBits(sclPort, sclPin);`。
- 违反上述任一条都属于超出需求的改动，须在动手前说明并征得用户同意。
