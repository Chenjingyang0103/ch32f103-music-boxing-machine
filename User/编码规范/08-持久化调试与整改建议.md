# 8. 持久化、调试与整改建议

> Flash 持久化模式、调试输出约定，以及归纳源码时发现的现存风格差异。

## 8.1 Flash 持久化

- 采用“魔数 + RAM 镜像 + 整块擦写”模式：
  - 固定数据区地址与块大小 `#define`，块大小为擦写对齐倍数；
  - 用魔数判断是否为首次写入；
  - 所有 `Set` 只改 RAM 镜像 `buf`，`Save` 才真正擦写 Flash；
  - `buf` 用结构体视图访问，避免手算偏移，并保留 `reserved` 自动补齐。

```c
typedef struct
{
    uint32_t magic;                                     // 魔数
    uint32_t cal[ADC_DEV_NUM][ADC_CAL_POINTS];          // 标定参数表
    float    rate[ADC_DEV_NUM];                         // 单点标定倍率
    uint8_t  reserved[MYFLASH_BLOCK_SIZE
                      - sizeof(uint32_t)
                      - (ADC_DEV_NUM * ADC_CAL_POINTS * sizeof(uint32_t))
                      - (ADC_DEV_NUM * sizeof(float))];
} MyFlashParamTypedef;
```

- 外部数据本体通过指针传入，模块内不持有业务数据。

## 8.2 调试输出

- 统一经 `debug.h` 的 `printf`，行尾一律 `\r\n`，输出中文提示便于串口助手阅读：

```c
printf("MyFlash: 擦除失败, status=0x%X\r\n", state);
printf("请放置 %s 砝码，等待稳定...\r\n", steps[i].name);
printf("击中靶子%d,{力度}%f\r\n", pRun->TargetNum, PeakForce);
```

- 大量调试打印默认以 `//` 注释保留，需要时再放开，避免影响实时性。

## 8.3 现存不一致与整改建议

以下为归纳源码时发现的风格分歧，新增代码请以本规范为准，改动旧代码时顺带对齐：

| 项 | 现状 | 建议 |
| --- | --- | --- |
| 缩进 | 统一 4 空格（`main.c` / `HCT6521.c` / `HCT6521.h` / `SM16028E.h` / `GameLogic.h` / `PunchDetect.h` 的 Tab 与 2 空格缩进已于全量复审中统一） | 保持 4 空格 |
| 头文件保护宏 | 统一 `__NAME_H`（`Key.h` 已由 `__KEY_H__` 改为 `__KEY_H`） | 保持 `__NAME_H` |
| 返回值注释 | 统一 `@retval`，不再使用 `@return` | 保持 |
| static 变量前缀 | 状态变量用 `s_`；参数数组 `AdcDeviceParam` / `PunchDeviceParam` / `SM28DeviceParam` / `WeightInfo` / `FilterInfo` **不加** `s_` | 按上述分类保持一致 |
| 模块头注释 | 大模块均有文件头 | 新增模块照此补全 |
| `#include` 顺序 | 统一为：自身 `.h` → 项目头 → 库头 → 标准库 | 保持 |
