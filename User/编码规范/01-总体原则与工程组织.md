# 1. 总体原则与工程组织

> 适用于 `User/` 下自研模块的总体设计约束与目录约定。

## 1.1 代码安全范围（硬性约束）

> ⚠ **强制边界：`.c` / `.h` 源文件只能改 `User/` 内的，其他文件夹下的源代码不允许更改。**

### 1.1.1 允许修改

- `User/` 文件夹下的全部 `.c` / `.h` 文件：

```text
User/
├── Inc/      (允许)
├── Src/      (允许)
├── ADC/      (允许)
└── Display/  (允许)
```

### 1.1.2 禁止修改（只读）

- `User/` 之外的所有源代码目录，一律只读，禁止修改、删除、重命名或移动：

```text
peripheral/   ← 库源码，只读
core/         ← 内核源码，只读
.cmsis/       ← CMSIS 头文件，只读
Debug/        ← 调试模块，只读
Startup*/     ← 启动文件，只读
Library/      ← 其他库，只读
```

**审查豁免**：以下 WCH 官方文件虽位于 `User/` 内，但属于库文件，**不在本规范审查范围内**，
不做格式 / 命名 / 注释整改，保持官方原始风格：

```text
User/Src/system_ch32f10x.c     User/Src/ch32f10x_it.c
User/Inc/system_ch32f10x.h     User/Inc/ch32f10x_it.h     User/Inc/ch32f10x_conf.h
```

> 如需改动上述文件，仍须先说明原因并征得用户明确同意（同 1.1.3）。

### 1.1.3 例外处理流程

| 情形 | 处理方式 |
| --- | --- |
| 需求只涉及 `User/` | 直接按本规范修改 |
| 需求疑似涉及 `User/` 之外的文件 | **先停止，不得改动**；向用户说明“需要改哪个文件、为什么、影响范围”，**经用户明确同意后**再操作 |
| 用户明确指示修改某个外部文件 | 以用户指令为准，但需在回复中提示该文件不在本规范保护范围内 |

### 1.1.4 检查清单（改动前自检）

1. 待改文件路径是否以 `User/` 开头？ → 否，则不得直接改。
2. 是否只是“查看 / 引用”外部文件？ → 是，可读，禁止写。
3. 是否已获得用户对改动外部文件的明确同意？ → 未获得则先询问。

## 1.2 总体原则

| 原则 | 说明 |
| --- | --- |
| 安全范围 | `.c`/`.h` 只改 `User/` 内文件，外部源码只读（见 1.1） |
| 分层 | 驱动 → 滤波 → 业务 → 显示，逐层单向依赖，禁止反向调用 |
| 封装 | 每个模块一个 `.c` + `.h`；内部状态用 `static` 隐藏，只暴露接口 |
| 集中配置 | 一切可调参数、设备号枚举统一放入 `Project_Config.h` |
| 非阻塞 | 主循环轮询 `XXX_Task()`，禁止在业务中长时间阻塞（标定流程除外） |
| 中文注释 | 注释使用中文，代码标识符使用英文 |

## 1.3 文件与目录组织

```text
User/
├── Inc/      模块头文件（.h）
├── Src/      模块实现（.c）与启动/中断相关文件
├── ADC/      ADC 驱动与称重链路（HCT6521 / Filter / Weight / Calibration）
└── Display/  数码管显示模块（SM16028E）
```

- 一个功能模块拆分为同名 `.h` / `.c`，例如 `PunchDetect.h` + `PunchDetect.c`。
- 中断服务函数放在其所属模块的 `.c` 中（而非集中塞进 `ch32f10x_it.c`）：
  - `Timer.c` → `TIM2_IRQHandler`
  - `MyRTC.c` → `RTC_IRQHandler`
  - `Key.c` → `EXTI9_5_IRQHandler`
- `ch32f10x_it.c` 仅保留内核异常处理（`NMI` / `HardFault` / `SysTick` 等）。

`main.c` 中的 `#include` 按模块分组、并用行尾注释说明用途：

```c
#include "debug.h"          // printf调试和delay延时

#include "MyRTC.h"
#include "HCT6521.h"        // AD采集
#include "MyFlash.h"        // 内部FLash存储

#include "Filter.h"         // 滤波
#include "Weight.h"         // 重量转换
#include "SM16028E.h"       // 数码管显示
#include "Timer.h"          // 系统计时
#include "PunchDetect.h"    // 拳击检测
#include "GameLogic.h"      // 游戏逻辑
#include "Project_Config.h" // 整个工程的配置文件
```

## 1.4 包含顺序

`.c` 文件的 `#include` 建议按以下顺序排列，各组之间空一行：

1. 自身模块头文件
2. 项目内自研头文件（`Project_Config.h` / 依赖模块）
3. 库头文件（`ch32f10x*.h`）
4. 标准库（`<string.h>` / `<stdlib.h>` / `<math.h>` / `<stdint.h>`）
