# STM32 工程编码规范

> 本文件（`User/STM32工程编码规范.md`）为**总纲 / 骨架**，仅保留目录索引与使用说明；
> 各项规范正文拆分为独立子文件，存放于同级的 [`编码规范/`](编码规范/) 目录，便于分模块维护与后续扩展。
>
> 归纳范围：`User/` 目录下全部源码（`Src`、`Inc`、`ADC`、`Display`）。
> 库文件（`peripheral/`、`core/`、`.cmsis/`、`Debug/`）沿用官方原始风格，不受本规范约束。

---

## 代码安全范围（硬性约束）

> ⚠ **这是本规范的强制边界，任何情况下不得突破。**

- 对 `.c` / `.h` 源文件，**仅允许修改 `User/` 文件夹内的文件**。
- `User/` 之外的任何源代码（如 `peripheral/`、`core/`、`.cmsis/`、`Debug/`、`Startup`、`Library` 等）
  **一律只读，禁止修改、删除、重命名或移动**。
- 若某项功能确实需要改动 `User/` 之外的文件，**必须先停止操作并向用户说明原因、征得同意**，
  不得擅自修改。详见 [01 代码安全范围](编码规范/01-总体原则与工程组织.md#11-代码安全范围硬性约束)。

## 如何扩展本规范

1. 在 `编码规范/` 目录下新增子文件，命名为 `编号-主题.md`（编号顺延，如 `09-xxx.md`）。
2. 在本文「目录」表格中追加一行，并在「快速检索」补充入口。
3. 子文件统一采用如下模板：

   ```markdown
   # 编号. 主题

   > 适用范围 / 一句话说明。

   ## 编号.1 小节标题
   ... 正文 ...

   ## 编号.2 小节标题
   ... 正文 ...
   ```

4. 修改某条规范时，只改对应子文件，无需改动本骨架文件。
